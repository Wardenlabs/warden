How it works

It runs before the prompt leaves the machine.

UserPromptSubmit hook

Claude Code and Codex

Not through a proxy the employee can point somewhere else — through each tool's own hook, which fires locally the moment they press Enter. This is what makes it work on subscription plans: a Claude Max or ChatGPT Plus session authenticates over OAuth against a fixed endpoint, so there is no base URL to redirect. The hook does not care. It runs first.

OpenAI-compatible proxy

Cursor, Open WebUI, any SDK

Anything that lets you set a base URL points at the local gateway instead. Same policy, same audit log, same verdicts — and output-scoped rules are judged on what the model answered, not only on what was asked.

on-device

Every model runs locally, through QVAC

Qwen3-1.7B judges each rule under a JSON-schema grammar at temperature 0 with a fixed seed. EmbeddingGemma-300M retrieves which rules are even relevant, by cosine similarity — no LLM in that step. OCR pulls text out of attachments before they are treated as the untrusted input they are. The company's rules, its documents and its conversations never leave the building.

append-only

The audit log keeps the hash, not the text

Every decision is chained and verifiable with npm run verify-audit. It stores the SHA-256 of a prompt and never the prompt itself — a log that kept the text would be a transcript of everything your employees typed, which is exactly what this refuses to be.

100% on four attack classes

Multi-turn escalation, language switching, paraphrase evasion and document-borne injection were each stopped 16 of 16 — the classes a system prompt has no answer to at all.

5.7× saved by asking for less

The verdict shape is {verdict} and nothing else. Adding one free-text reason field — the design this started with — cost 5.7× on latency and produced JSON that would not validate. The explanation is composed in code from the ratified rule instead.

What does not work yet

The number we are least proud of.

A guard that refuses everything scores 100% on attacks and is unusable. Both numbers get reported, because the second one decides whether anyone leaves it switched on.

58% of legitimate traffic is wrongly refused

21 of 36 clean requests were blocked. Fourteen of them came from a single rule, r-instruction-override, which is also the cheapest thing in the system to fix — reword it, or add the requests it wrongly blocked to its examples.compliant. That is the anchor the adjudicator actually reads.

Two attack classes are weak for the same reason and we have not fixed them either: guard-targeted stopped 8 of 16, and volume-distraction 2 of 8. The hook integrations for Claude Code and Codex remain not verified end to end — a Windows run observed both correct blocks and false-positive ones, and a cold Codex decision that overran the 30-second deadline and reached the model.

All 45 wrong evaluations are listed individually in REPORT.md, with the prompt and the rule that fired, so this can be checked rather than taken on trust.
